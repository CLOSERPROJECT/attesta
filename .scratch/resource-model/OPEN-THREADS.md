## Doc fixes (decided, not yet written)

- **Step 2 replay test misses `CloseGroup` and stored timestamps.** `docs/vision.md` step 2 says to add a replay test that rebuilds the `Domain` from `Submissions`, but `CloseGroup` (`server/internal/living/groups.go:143`) appends to `Domain.ClosedGroups` without creating a `Submission`, and `Commit` (`server/internal/living/commit.go:224`) reads the wall clock once per commit. Step 2 in `docs/vision.md` must state that group-close actions are also wrapped in an Observation envelope and that replay reuses each record's stored timestamp. *(Sources: `docs/vision.md` "Suggested sequence"; `attesta-screens-followups-handoff.md` "How we got here", "Suggested next work"; `attesta-scopes-rea-handoff.md` "Review findings still open")*
- **`pallet_weighed` derived `panel_count` uses bare `tare`.** Both `docs/interpretation-package.md` and `docs/sketch.yaml` write `expr: $floor(($input.gross_weight - tare) / $input.average_panel_weight)` under `pallet_weighed.derived.panel_count`, referencing the pallet's `computed` property `tare` before `write` has populated the pallet's fields. Fixing the expression is coupled with deciding whether `derived` input expressions may read only `$input`, `$subject`, and `$catalogs` or may evaluate previewed `computed` properties. *(Sources: `docs/interpretation-package.md` "Event types"; `docs/sketch.yaml` `events.pallet_weighed`; `attesta-screens-followups-handoff.md` "How we got here", "Suggested next work"; `attesta-scopes-rea-handoff.md` "Review findings still open")*
- **Determinism rule for `$today` capture-time defaults.** `docs/sketch.yaml` uses `default: $today` on `working_day_started.input.date`, which preserves deterministic replay only if evaluated at capture time so the resolved date is stored in the Observation payload. `docs/interpretation-package.md` needs an explicit rule allowing `$today` only as a capture-time input default and forbidding wall-clock evaluation during reconstruction. *(Sources: `docs/sketch.yaml` `events.working_day_started`; `attesta-screens-followups-handoff.md` "How we got here", "Suggested next work"; `attesta-scopes-rea-handoff.md` "Review findings still open")*
- **Shortened fixture path and ephemeral `.scratch` link in `vision.md`.** `docs/vision.md` writes `fixtures/feragame-config.yaml` instead of `server/internal/living/fixtures/feragame-config.yaml` and references `.scratch/living-flat-port/issues/13-rename-placeholders-discussion.md`, which is untracked local state. Both references in `docs/vision.md` should be corrected. *(Sources: `docs/vision.md` "Modify", "Retire or decide"; `attesta-scopes-rea-handoff.md` "Review findings still open")*

## Design questions — authoring model

- **Top-level package schema and expression syntax.** YAML in `docs/interpretation-package.md` is marked illustrative, and the spec leaves the grammar for `views`, `prompts`, `checks`, and `computed` properties open. In addition, `docs/sketch.yaml` uses top-level keys (`actors`, `catalogs`, `views`, `passports`), type/event keys (`display`, `effects`, `eligible_when`, `sealed_by`), and helper functions (`$within`, `$seq`, `$sum`) that are not yet defined in `docs/interpretation-package.md`. *(Sources: `docs/interpretation-package.md` intro, "Open questions"; `.scratch/resource-model/COORDINATOR.md` "Open points"; `attesta-screens-followups-handoff.md` "How we got here"; `attesta-scopes-rea-handoff.md` "Review findings still open")*
- **References outside the navigation context.** References are resolved at capture time from the screen's navigation path (`$context.*`) and stored as IDs in the Observation. It remains open how an event type declares and resolves a reference when the target resource or scope is not on the navigated path, such as when an operator opens a resource directly via a QR scan. *(Sources: `docs/interpretation-package.md` "Requirement: References are resolved at capture", "Open questions"; `.scratch/resource-model/COORDINATOR.md` "Open points"; `attesta-screens-followups-handoff.md` "Still open")*
- **ADR coverage for screens/follow-ups and reopening ADR-0005, ADR-0006, and ADR-0007.** Decisions 8–13 (screens, context-resolved references, `available_when`, container handoff state, and `also` follow-ups) do not yet have their own ADR (note that `ADR-0010` was subsequently assigned to scopes and REA declarations), and `ADR-0005`, `ADR-0006`, and `ADR-0007` still need to be formally reopened alongside promoting target vocabulary into `GLOSSARY.md` when code lands. *(Sources: `docs/vision.md` "ADRs this reopens"; `docs/interpretation-package.md` "Mapping from today's Org Config"; `attesta-vision-handoff.md` "ADRs that conflict with offline / ungated capture", "Suggested next work"; `attesta-screens-followups-handoff.md` "Still open", "Suggested next work")*
- **End-to-end Feragame parity check on `sketch.yaml`.** Before porting Feragame in step 3, `docs/sketch.yaml` needs a systematic comparison against every task in `server/internal/living/fixtures/feragame-config.yaml` (`intake` `truckArrive`/`lots`/`weightCheck`, `line` `openTurno`/`palletWeight`/`lineLoad`/`containerReg`, and `passport`) to verify no fields or sidecar effects were missed. *(Sources: `attesta-resource-model-handoff.md` "Natural next work")*

## Design questions — capture, UI, offline

- **Correcting a trigger that sent `also` follow-ups.** When an action emits follow-up Observations via `also` (for example, the first `pallet_weighed` triggering `lot_started` and `container_taken_over`), voiding the trigger raises the question of whether its follow-ups are voided automatically or only offered for voiding in the GUI. `docs/interpretation-package.md` writes that each Observation is corrected on its own and the GUI *may* offer to correct them together, while `COORDINATOR.md` and `attesta-screens-followups-handoff.md` keep the question open for the human and recommend offering in the GUI with checks catching leftovers. *(Sources: `docs/interpretation-package.md` "Requirement: One action may send several Observations"; `.scratch/resource-model/COORDINATOR.md` "Open points"; `attesta-screens-followups-handoff.md` "Still open")*
- **Correction rights.** It is undecided who is permitted to submit a correction Observation: any operator holding one of the original event type's roles, a supervisor, or a reviewer in the Review workspace. *(Sources: `docs/interpretation-package.md` "Open questions")*
- **Offline workflow completeness scope.** It is undecided whether an offline device must be able to execute an entire plant workflow standalone or only its workstation's slice, which governs how much of the package, reference data, and central projections each device carries. *(Sources: `docs/vision.md` "Requirement: Local provisional reconstruction", "Open decisions"; `attesta-vision-handoff.md` "Open decisions")*
- **Portable reconstruction engine runtime.** Running identical reconstruction and board rules on the device and on the server requires choosing between compiling the Go engine to WebAssembly or restricting rules to JSONata expressions with a shared evaluator posture across Go and the SPA. *(Sources: `docs/vision.md` "Add" > "Local reconstruction and local world model", "Open decisions"; `attesta-vision-handoff.md` "Open decisions")*
- **Offline effects.** Package effects (such as printing pallet labels or generating CSVs) run after central reconstruction by default; if operators need generated labels at the workstation while offline, the device will need a local effect runner. *(Sources: `docs/vision.md` "Open decisions"; `attesta-vision-handoff.md` "Open decisions")*

## Design questions — reconstruction, review, publication

- **Ordered display labels and `$seq`.** Resource IDs are minted on the device, while human-readable display labels such as `C-N` or a lot's per-client progressive number require a deterministic order that cannot be arrival order. The candidate orders are occurrence time, device sequence, or assignment at Seal time; `docs/sketch.yaml` already uses `$seq` in `display` expressions, which presumes an answer to this question. *(Sources: `docs/interpretation-package.md` "Identity", "Open questions"; `docs/sketch.yaml` `scopes.truck`, `resources.lot`, `resources.container`; `attesta-screens-followups-handoff.md` "How we got here"; `attesta-scopes-rea-handoff.md` "Review findings still open")*
- **Review case granularity.** It is undecided whether Review cases and Seals are scoped to a lot, a scope instance (such as a working day or shift), a passport subject, a time period, or a combination of these. *(Sources: `docs/vision.md` "Requirement: Review case scope", "Open decisions"; `attesta-vision-handoff.md` "Open decisions")*
- **Provisional identity merge policy.** When central reconstruction resolves two device-minted provisional resources into one (or splits one into two) via an identity-resolution record, it is undecided whether unambiguous cases merge automatically or always require reviewer confirmation. *(Sources: `docs/vision.md` "Requirement: Explicit identity resolution", "Open decisions"; `attesta-vision-handoff.md` "Open decisions")*

## Product / scope

- **Fate of the Stream surface (`/my`).** The older linear, multi-party Stream surface still runs alongside Living (`/app`), whereas cross-company material flow in the target architecture is handled by the Federation gateway. Whether `/my` is retired, frozen, or migrated is an open product decision. *(Sources: `docs/vision.md` "Retire or decide", "Open decisions"; `attesta-vision-handoff.md` "Open decisions")*
- **Replacing the `living` placeholder name.** The Go package (`server/internal/living`), HTTP routes (`/api/living/*`), Cerbos policy kind, and seed environment variables still use the `living` placeholder; the rename remains paused until the target vocabulary lands in code. *(Sources: `docs/vision.md` "Retire or decide"; `attesta-resource-model-handoff.md` "Natural next work")*

## Deferred by the human (do not design until asked)

- **Computing REA flows, stock balances, and flow-derived passports.** Packages declare `agents`, resource `quantity` properties, per-event `rea` flows, and `processes` now so captured history is replayable into an REA ledger, but reconstruction derives nothing from them yet. Designing flow computation—including when to build the passport from `lot_processing` flows and how paired inter-company transfer events work—is deferred until the first real transformation or inter-company transfer requires it. *(Sources: `docs/interpretation-package.md` "REA declarations", "Open questions"; `docs/vision.md` "Modify", "Suggested sequence" step 7; `.scratch/resource-model/COORDINATOR.md` "Decisions" #3 and #14, "Open points"; `attesta-scopes-rea-handoff.md` "Decisions taken this session", "Open thread")*
- **Multi-observation event correlation and machine ingestion.** Correlating multiple Observations (such as a human report and a scale reading) into a single economic event and ingesting machine/ERP Observations are kept in the target architecture (`docs/vision.md` step 7), while `docs/interpretation-package.md` assumes one Observation per event for now. *(Sources: `docs/vision.md` "Requirement: Observation and event are distinct", "Capability: Machine ingestion (future)", "Suggested sequence" step 7; `docs/interpretation-package.md` "Vocabulary"; `.scratch/resource-model/COORDINATOR.md` "Vocabulary")*
- **Planning (commitments) and review-workspace collaborative editing.** Valueflows commitments/planning and real-time collaborative editing (OT/CRDT) inside the review workspace are explicitly deferred out of scope. *(Sources: `docs/vision.md` "Out of scope (for now)")*
