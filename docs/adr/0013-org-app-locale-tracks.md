# `/app` locale is three copy tracks; SPA Paraglide, plant Config pass-through, English engine v1

Operator-facing text on the Org SPA splits into **three tracks** that must not be merged into one catalog:

1. **SPA shell chrome** — generic executor UI (home, nav, scan, overview/task shells, handoffs, status tags, load/commit prefixes, empty/loading, port fallbacks, SJSF/Ajv *form chrome*) is **Paraglide** (`m.*` in `app/messages/{en,it}.json`). Hardcoded English *or* scattered hardcoded Italian helpers belong here until migrated; **plant-specific Italian from Org Config does not**.
2. **Plant product copy** — Worklist wire, task form bundle (`schema` / `uiSchema` / `chrome` / `dataReport`), and QR resolve `422` bodies are **Org Config YAML**, server-projected **display-only pass-through** on the SPA. Plants localize by authoring Config (or future per-org versions), not by duplicating titles into Paraglide. **Reject** moving Feragame YAML labels, enumNames, or `qr.messages` into SPA message catalogs.
3. **Platform engine / HTTP fallbacks** — Commit/Close denial bodies, QR infrastructure errors, load failures, and bare `http.Error` text from Go stay **English in v1**. The SPA may Paraglide-frame them (e.g. “Commit denied:”) but must not translate server bodies client-side.

**v1 locale strategy:** `baseLocale: it` in Inlang; resolution **`["cookie", "globalVariable", "baseLocale"]`** with cookie name `PARAGLIDE_LOCALE`. Cookie-less shared plant devices default to Italian without consulting **Accept-Language** (`preferredLanguage` is out of strategy — laptops must not flip kiosk tablets). Engineering English uses a **hidden** in-app control that calls **`setLocale('en')`** (cookie persistence), not URL-prefix locale links. **Defer URL-prefix locales** (`/it/app/...` or `/app/it/...`): default Paraglide `/:locale` patterns conflict with **`paths.base: '/app'`**, CSR (`ssr = false`), **sv-router** base-stripped paths, and **Go static** serve of `app/build` — production **does not** run `paraglideMiddleware`, so locale is client-side after bundle load; `<html lang>` must be synced on the client (`document.documentElement.lang` from `getLocale()`).

**Identifiers vs copy:** Config **role slugs** on the wire (`administration`, `logistic`, …) are identifiers, not product copy unless plants later add display names via Config or a mapping layer.

**Considered options:** (1) Single Paraglide catalog for all operator-visible strings including schema titles — rejected: duplicates plant YAML, couples releases to every label change, violates dumb executor. (2) `preferredLanguage` / Accept-Language for `/app` — rejected: unstable on shared devices. (3) URL-prefix locale in v1 with default Paraglide patterns — rejected: misaligned with `/app` mount and Go SPA fallback. (4) Localize Go Commit/QR engine messages in the SPA i18n project — rejected: platform copy; separate effort or Config-owned denial text later. (5) Dual-locale Config (`title_it` / `title_en`) as prerequisite for Italian `/app` — rejected: Feragame is already Italian in Config; dual-locale is an org-authoring product, not Paraglide.

**Consequences:** Agents implement track 1 via Paraglide + SJSF adapter + `ajv-i18n` (see [`docs/agents/app-i18n.md`](../agents/app-i18n.md)); track 2 unchanged on the wire; track 3 listed as known English gaps. E2e and unit tests assert Italian chrome by default where migrated. Optional guardrail: no new hardcoded EN/IT literals under `app/src/lib/org/` or `app/src/lib/router/` outside catalogs.
