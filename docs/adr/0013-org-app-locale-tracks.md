# `/app` locale is three copy tracks; SPA Paraglide, plant Config pass-through, English engine v1

Operator-facing text must not collapse into one catalog: generic chrome, plant-authored copy, and platform engine errors have different owners and change rates.

**Decision:** `/app` copy is three tracks. (1) **SPA shell chrome** (home, nav, scan, shells, status tags, form chrome, …) is Paraglide—hardcoded EN/IT helpers migrate here; plant-specific Config Italian does not. (2) **Plant product copy** (Worklist, task form bundles, QR resolve messages) is Org Config YAML, server-projected pass-through; plants localize by authoring Config, not by duplicating titles into Paraglide. (3) **Platform engine / HTTP fallbacks** stay English in v1; the SPA may frame them but must not translate server bodies client-side. v1 locale defaults to Italian via cookie (no Accept-Language on shared plant devices); engineering English is an in-app control, not URL-prefix locales. Config role slugs on the wire are identifiers, not product copy.

**Considered options:** Single Paraglide catalog including schema titles; Accept-Language for `/app`; URL-prefix locale in v1; localize Go engine messages in the SPA i18n project; dual-locale Config fields as a prerequisite for Italian `/app`. Rejected for dumb-executor coupling, unstable shared devices, `/app` mount constraints, and keeping platform vs plant copy ownership clear.
