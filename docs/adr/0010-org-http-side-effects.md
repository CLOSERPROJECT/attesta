# Org Config declares post-Commit HTTP side effects as paths; platform owns peers and browser proxies

**HttpPort** (`onSubmit.http`) runs **after** a successful Domain mutate on Commit. Config authors declare side effects as **opaque path-shaped** identifiers (template-evaluated strings), not absolute URLs or caller-chosen hosts. The platform joins each path to an **Adapter** target using deployment env (base URL, shared secrets); Org Config never holds credentials or peer hostnames. Failures are **soft**: HttpPort errors are surfaced on the Commit response but **do not** roll back the Domain write.

**Seam (locked):** Config says *which* effect paths fire for a Task; Go resolves path → Adapter, calls it with server-held auth, maps responses into Commit **links**, and rewrites fetchable artifact locations into Attesta URLs the SPA may use. The `/app` SPA and browser **never** call the Adapter directly. Artifact GETs go through an Attesta **authorized proxy** (session + org binding on stored artifact meta). Absolute `http://` or `https://` values from evaluated Config are **rejected** so operators cannot steer the server toward arbitrary hosts (SSRF).

**Not locked (reversible adapters):** Today's default Adapter may be an in-repo plant peer on the internal Compose network; effect path strings may look like HTTP URL paths. Per-Organization allowlisted peers, outbound automation (e.g. n8n), and multi-tenant credential wiring are **unknown future** integration and may supersede the default peer without changing the Config seam (path-only declarations, platform-owned resolution, proxy-only browser access, soft failures).

**Considered options:** (1) Absolute URLs in Org Config — rejected: SSRF and secret sprawl. (2) Browser fetches Adapter artifact URLs — rejected: bypasses Attesta session/org gate. (3) Roll back Domain on HttpPort failure — rejected: side effects are ancillary to authoritative mutate. (4) Embed shared secrets in Config — rejected: secrets belong in deployment env only. (5) Lock the plant sidecar as the only Adapter forever — rejected: seam is HttpPort + resolution rules; peer implementation may change. (6) Return `data:` bodies as Commit links — rejected: artifacts are fetchable URLs rewritten for the proxy.

**Consequences:** Org Config and glossary **HttpPort / onSubmit.http** stay path-shaped; product wiring supplies a real HttpPort client when env is set (tests keep fakes). Need SSRF validation on evaluated URLs, timeouts and soft error mapping, artifact id generation with org binding, and an Attesta GET proxy ahead of any peer fetch. External multi-peer HttpPort is explicitly deferred until a later ADR may extend resolution without reopening the locked seam.
