# Living `/app` operator home is a viewer-scoped Worklist with Task and overview routes

Living operators land on a **Worklist** home (Available Tasks + Can start Jobs), not the prior flat JobPanel board and not legacy `/my`. Available rows are flat and keyed by `jobId` / `jobInstanceId` / `taskId`; home stays actionable-only. Working a Task uses `/app/{jobId}/{jobInstanceId|new}/{taskId}`; handoff uses a **Job instance overview** at `/app/{jobId}/{jobInstanceId}`. After Commit, the SPA auto-advances when the same **OperatorIdentity** has another role-eligible `available` Task on that instance; otherwise it opens the overview (or home when the instance is finished). Available / Can start / auto-advance use authored Config-role intersection for board chrome; **Cerbos** remains authoritative on Commit. Home Load ships viewer-scoped Worklist (with Task title + roles chrome) without bulk **Task form bundle**s; bundles load on Task open; Commit returns updated Worklist and the next bundle when advancing. **readyWhen** stays Commit-only (ADR-0005). This amends ADR-0005’s “ship every available bundle on Load” policy for the operator home path. Stream Operator home and the Stream timeline accordion stay out of scope.

**Considered options:** (1) Keep inline JobPanel forms on a single `/app` page — rejected: no deep links, weak handoff, heavy Load. (2) Role-blind Worklist with client filtering from Org Config — rejected: Config must stay off the wire; “mine” must be server-projected. (3) Cerbos round-trip per Worklist row — rejected: board chrome stays slug∩roles; Commit keeps Cerbos. (4) Always return to home after Commit — rejected: same-role auto-advance and explicit overview handoff match plant handoffs.

**Consequences:** Living demo seed needs role-split users and multi-stage Domain so each home differs. Overview and Task routes replace “instance tree on home.” SPA must not re-derive Unlock / startsWhen / role eligibility from a full Org Config snapshot.
