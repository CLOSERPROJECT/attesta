# Org QR encode and resolve are Config-declared; Go owns eligibility and Worklist match

Operators scan or paste cold links to reach actionable Tasks with optional form seed. Plant eligibility, destination, seed, and errors must not live in a Svelte rule engine or in browser calls to plant peers.

**Decision:** Encode and resolve are one platform capability. Org Config declares a root **`qr`** block of ordered rules (sibling of `domain` / `passport` / `stream`); Go evaluates Domain and the server-projected Worklist ([ADR-0005](0005-org-worklist-server-projection.md)) within the **Org stream** and returns navigation plus seed. Resolve is **stream-scoped**: a hit that belongs to another **Org stream instance** of the same stream **jumps** the operator into that instance’s `/app` view ([ADR-0014](0014-org-config-as-stream.md)). The SPA captures **raw** bytes only and applies that outcome ([ADR-0009](0009-org-client-draft-persistence.md))—it must not re-run eligibility or re-project Worklist. Platform facts (not Config): public cold-link base for encode bindings, and a fixed decode of raw → scan entity id (no Config `parse` hook). Camera/decoder libraries are reversible; v1 may treat a single Worklist match as the happy path—multi-match picker UX is deferred, not forbidden.

**Amended by [ADR-0014](0014-org-config-as-stream.md):** stream scope and cross-instance jump as above.

**Considered options:** SPA-side `qr.rules` engine; browser→plant decode before resolve; Config-authored `parse` for every label format; resolve match only on Tasks with no root `qr` block; lock one camera library forever; forbid multiple candidates permanently; treat the demo plant YAML as the feature; plant-wide QR without instance jump. Rejected for dumb-executor / session-boundary reasons and to keep the seam Config rules + server resolve.
