# Living QR encode and resolve are Config-declared; Go owns eligibility and Worklist match

Living operators scan or paste cold-link strings to jump into actionable Tasks with optional form **seed**. **Encode** (labels, sidecar PDFs, HttpPort bodies) and **resolve** (topbar Scan, deep links into `/app`) are one platform capability: Org Config declares *which* rules apply and *how* to match the viewer Worklist; Go evaluates Domain + Worklist and returns navigation and seed; the living SPA captures **raw** bytes only and applies the server outcome. Plant business rules (eligible entity, destination Task, seed fields, operator-facing errors) live in Config—not in Svelte rule engines and not in browser calls to plant peers.

**Config shape (locked):** Root **`qr`** block (sibling of **`domain`** and **`passport`**, per [ADR-0007](0007-living-passport-production.md)) holds ordered **`rules`**. Each rule may carry **`when`**, **`match`** (job / optional group / task, plus spawn policy), **`eligible`** (JSONata over Domain + scan binding), **`seed`**, and **`messages`**. Encode strings are Config-authored (e.g. `$qrEndpoint & "?entityId=" & $id` on register labels); sidecars and HttpPort draw opaque QR payload—they do not interpret resolve law.

**Resolve seam (locked):** Authenticated client **`POST`s `{ raw }`** only (paste or camera decode). Go **`ResolveQR`** runs against the operator org, token-bound Domain, and server-projected Worklist from [ADR-0005](0005-living-worklist-server-projection.md). First **`when`**-matching rule owns the outcome: **`eligible`** failure → configured error; Worklist **`match`** yields candidates → **`navigate`** + evaluated **`seed`** on success, or **`zero` / `many` / `seed`** errors with authored **`messages`**. SPA navigates and **`setDraft`** from the response ([ADR-0009](0009-living-client-draft-persistence.md)); it must **not** re-run eligibility, re-project Worklist, or branch on plant-specific predicates. v1 Scan may treat a single candidate as the happy path and surface **`many`** as a toast; **multi-match picker UX is deferred, not forbidden**—this ADR does not lock “exactly one candidate forever.”

**Platform facts (locked, not Config):** **`$qrEndpoint`** / public cold-link base = **`PUBLIC_BASE_URL`** (trim trailing `/`) + **`/app`**, injected for Commit/HttpPort JSONata like other submit bindings. **Decode** of `raw` → **`scan.entityId`** is a fixed Go convention (URL query **`entityId`**, tolerant fragment, or bare id)—**no Config `parse`** hook. Org scope comes from the session token.

**Not locked (reversible mechanisms):** Camera + barcode decode library (today **`cam2qr`** in ScanDialog per plant delivery notes) is an implementation choice; paste + **`{ raw }`** resolve law is unchanged if the decoder changes. **`$place`** narrowing on resolve, browser→plant decode, and richer **`many`** UX remain deferred.

**Considered options:** (1) SPA-side rule engine mirroring **`qr.rules`** — rejected: duplicates Worklist projection and Domain law; violates dumb executor. (2) Browser → plant Adapter decode before resolve — rejected: bypasses Attesta session/org gate (cf. [ADR-0010](0010-living-http-side-effects.md)). (3) Config-authored **`parse`** for every label format — rejected for v1: one platform decode keeps Scan thin; plants encode toward **`entityId`**. (4) Embed resolve **`match`** only in Task routes with no root **`qr`** block — rejected: same failure mode as passport without root block; duplicates scheme across entry points. (5) Lock **`cam2qr`** as the forever decoder — rejected: library is consequence; seam is **`{ raw }`** + server resolve. (6) Forbid multiple Worklist candidates permanently — rejected: engine already returns **`many`**; only v1 operator UX is narrow. (7) Lock Feragame pallet-weigh YAML as the feature — rejected: fixture is one payload instance, not product law.

**Consequences:** Org Config validation for **`qr.rules`** shape; HTTP resolve handler wired to **`ResolveQR`**; SPA ScanDialog stays transport-only; label/register authors use **`$qrEndpoint`** in Config exprs; tests cover zero/one/many/ineligible against projected Worklist. Glossary may add **QR resolve** / cold link vocabulary. Follow-on ADRs may define multi-match UX or **`$place`** without reopening Config ownership of rules or server-side eligibility.
