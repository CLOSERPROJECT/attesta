# Org operator Draft lives in OrgSession; dirty-only client persist and Bozza chrome

Operators need in-progress Task data before Submission without turning Draft into Domain, Worklist status, or entity progress—and without a second draft/publish concept from Formata ([ADR-0002](0002-affiliation-gated-stream-authoring.md)).

**Decision:** **Draft** is client-only working data. **OrgSession** is the single writer: seed from Load/Commit without marking dirty; operator/QR edits mark dirty until successful Commit clears that address. Only dirty Drafts persist across reload and drive muted **Bozza** chrome beside existing Worklist status—not a sixth `TaskStatus`, not `hasDraft` on Go projections ([ADR-0005](0005-org-worklist-server-projection.md)). Seed/schema defaults alone must not mark or persist. v1 persistence is browser-local and reversible; server DraftPort, multi-tab merge, and orphan GC are deferred and may change storage without reopening Session-as-source-of-truth or Worklist enum law.

**Considered options:** (1) Separate DraftStore/DraftSession beside OrgSession — rejected: dual writers. (2) `hasDraft` on Worklist/Go — rejected: projections stay pure. (3) Persistence inside form factories — rejected: belongs at session boundary. (4) Any non-empty bag as dirty — rejected: seed/defaults are not WIP. (5) Bozza as Worklist `draft` status — rejected: conflates chrome with Unlock/Submission/readyWhen. (6) Rehydrate from storage on every Load refresh — rejected: clobbers in-memory dirty. (7) Server DraftPort in v1 — rejected scope.
