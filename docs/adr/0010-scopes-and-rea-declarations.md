# Scopes are not resources; REA is declared before it is computed

The Interpretation package declares **scopes** (working day, shift, a truck being unloaded) in their own section, next to **resources** (lot, pallet, container). Both have lifecycles, containment, and can be event subjects; only resources have a `quantity` and take part in flows. The package also declares, without the engine computing anything from them yet, its **agents** (Feragame's clients), a `quantity` per resource type, a `rea` flow per event type that moves material (Valueflows action, resource, quantity, provider, receiver), and **processes** as readings of events (`lot_processing`: pallets consumed in, containers produced out). See [`docs/interpretation-package.md`](../interpretation-package.md), sections Scopes and REA declarations.

We chose this because the target model is REA (`docs/vision.md`), and history captured from now on must be replayable into it. Declarations cost one line per event type today; reconstructing REA later from untyped references would mean mapping every event type by hand. Separating scopes lets the registry enforce that a shift or truck never flows, so a later REA ledger does not show lots as outputs of a shift.

**Considered options:** (1) Scopes as resources, as in the first draft (ADR-0008, ADR-0009) — rejected: nothing would stop a working day from receiving a quantity or a flow. (2) Shifts and working days as REA processes — rejected: a process transforms resources, and a shift transforms nothing; every lot handled in a shift would read as its input or output. (3) One `entities` section with resources and scopes inside — rejected: "entity" is today's Domain vocabulary (`GLOSSARY.md`) and the nesting adds no rule, since names must be unique across both anyway. (4) Name the section `contexts` — rejected: context already means the operator's navigation path (`$context.lot`), which includes resources. (5) Compute flows now — deferred, as in ADR-0009, until the first real transformation between companies.

**Consequences:** ADR-0009's subject and reference are now "a resource or a scope". The package registry validates the declarations (Valueflows actions, units on quantities, no flows on scopes) but reconstruction ignores them until flows are computed. A resource's `quantity` is written only by events that measure it; amounts that follow from flows are computed properties. A resource may have several quantities in different units: a pallet flows as kilograms and panels. Registering a lot is a `transfer` (ownership and custody) from the client. Open: when flows are computed, expected for building the passport and for transfers between companies.
